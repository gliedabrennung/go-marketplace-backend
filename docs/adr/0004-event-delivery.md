# ADR-0004. Доставка доменных событий без внешнего брокера

**Статус:** Принято · **Дата:** 2026-09-16

## Контекст

Модульный монолит (ADR-0001) работает с одной базой PostgreSQL. Внешний брокер (Kafka, NATS) добавляет отдельную инфраструктуру, эксплуатацию и точку отказа, при этом согласованность «изменил агрегат + опубликовал событие» всё равно требует Transactional Outbox. Заказчик исключил брокер из объёма работ.

## Решение

- События пишутся в `platform.outbox` в транзакции агрегата (`outbox.Writer`, вызывается из `Save` репозитория).
- Процесс `worker` запускает `outbox.Relay` с `outbox.Dispatcher`:
  - выборка пачки `FOR UPDATE SKIP LOCKED` в порядке `id`, активен один экземпляр (`pg_try_advisory_xact_lock`);
  - каждое событие передаётся подписчикам, зарегистрированным по имени события (`outbox.Subscription`);
  - для каждого подписчика обработка регистрируется в `platform.processed_messages (consumer_group, message_id)` в одной транзакции с проверкой — повторная доставка не создаёт дублирующих эффектов;
  - если хотя бы один подписчик вернул ошибку, событие остаётся неопубликованным, `attempts` увеличивается, повтор — с экспоненциальной задержкой; более поздние события того же агрегата в пачке не доставляются, пока не пройдёт предыдущее;
  - после 10 попыток событие не выбирается и попадает в метрику `outbox_stuck_messages`;
  - события без подписчиков помечаются опубликованными сразу.
- Подписчики объявляются модулями контекстов (`identity.Worker.Subscriptions()`) и собираются в `cmd/worker/main.go`.
- Контекст трассировки и `request_id` передаются через колонку `metadata`.

## Метрики

`outbox_lag_seconds`, `outbox_stuck_messages`, `outbox_published_total`, `outbox_publish_failures_total`, `outbox_handler_total{consumer,event_name,outcome}`.

## Последствия

- Нет отдельной инфраструктуры; доставка at-least-once с дедупликацией; порядок гарантирован в рамках агрегата.
- Пропускная способность ограничена одним активным диспетчером и временем обработчиков; при росте — партиционирование по хэшу `aggregate_id` с несколькими advisory-блокировками.
- Подписчики выполняются в процессе `worker`: медленный обработчик задерживает остальные события пачки, таймаут пачки — `OUTBOX_DISPATCH_TIMEOUT`.
- Внешним потребителям (BI) события доступны в `platform.outbox` до очистки (`OUTBOX_RETENTION`, по умолчанию 7 дней).
- При выделении сервиса `outbox.Publisher` заменяется адаптером внешней шины без изменения доменов и Writer.

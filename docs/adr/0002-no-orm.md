# ADR-0002. Отказ от ORM в пользу ручного маппинга

**Статус:** Принято · **Дата:** 2026-09-15

## Контекст

Агрегаты инкапсулированы: поля неэкспортируемые, создание только через фабрики. ORM требует экспортируемых полей с тегами или рефлексии по приватным полям, что ломает инкапсуляцию и тянет инфраструктуру в домен.

## Решение

- Драйвер `pgx/v5`, пул `pgxpool`, без ORM и без генераторов, влияющих на доменные типы.
- Каждый репозиторий — `internal/<context>/infrastructure/postgres`, маппинг domain ⇄ persistence — `mapper.go` того же пакета.
- Восстановление агрегата из хранилища — через экспортируемую функцию-реконструктор домена (`Rehydrate…`), которая не порождает событий и не валидирует переходы.
- SQL только параметризованный (`$1…$n`). Имена таблиц — константы в коде, при необходимости экранируются `pgx.Identifier`.
- Транзакционная граница — `postgres.UnitOfWork[R]`, где `R` — интерфейс набора репозиториев, объявленный в `application`.
- Read-модели — прямой SQL под экран, минуя агрегаты.

## Последствия

- Полный контроль над запросами, индексами и блокировками (`FOR UPDATE`, `SKIP LOCKED`).
- Больше ручного кода маппинга; компенсируется интеграционными и contract-тестами репозиториев.
